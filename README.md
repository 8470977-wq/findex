# findex — Пошукова система (Лабораторна 2)

## Особливості реалізації Лабораторної 2
- **Моделі даних**: Використано `@dataclass(frozen=True, slots=True)` для класів `Posting` та `DocMeta`.
- **Boolean-пошук**: Реалізовано алгоритм перетину відсортованих списків двовказівниковим методом (`merge`) та альтернативу на базі Python `set`.
- **Серіалізація**:
  - `pickle` (бінарний формат з високою швидкістю).
  - `json` (людиночитаний формат).
  - *Примітка щодо безпеки:* Використання `pickle.load` з невідомих джерел є небезпечним, оскільки десеріалізація може виконувати довільний Python-код через механізми `__reduce__`.

## Порівняння пам'яті залежно від структури постінгів

| Варіант збереження | Пікова пам'ять (MB) |
| :--- | :--- |
| **Standard Class** | ~0.45 MB |
| **Dataclass (`slots=True`)** | **~0.25 MB** |
| **`array('I')`** | **~0.12 MB** |

### Куди пішли байти?
1. **Standard Class**: Кожен об'єкт створює динамічний словник `__dict__`, який витрачає додаткову пам'ять під хеш-таблицю атрибутів об'єкта.
2. **Dataclass (`slots=True`)**: Скасовує створення `__dict__` і фіксує розмір екземпляра у вигляді масиву вказівників фіксованої довжини в C-структурі Python.
3. **`array('I')`**: Виключає накладні витрати на обгортки об'єктів Python (`PyObject`), зберігаючи значення як суцільний блок пам'яті 32-бітних беззнакових цілих чисел у C-форматі.

## Порівняння двигунів пошуку (Merge vs Set)

| Запит | Engine = merge (s) | Engine = set (s) |
| :--- | :--- | :--- |
| **Часті терми (AND)** | 0.00012 s | 0.00018 s |
| **Рідкісні терми (AND)** | 0.00005 s | 0.00008 s |

## CLI Інтерфейс
- **Побудова індексу**: `python -m findex.cli_index data/ --out index.bin`
- **Пошук**: `python -m findex.cli_search index.bin "term1 term2" --engine merge`
